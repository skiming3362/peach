# ADR-0162：存进文件与账本的取值用英文稳定 id

- 状态：已采纳
- 日期：2026-11-14
- 关系：补充 [ADR-0159](0159-interface-text-lives-only-in-locale-resources.md) 第四条（内容数据）与第五条（旧记录转换）；账本迁移照 [ADR-0126](0126-upgrade-effective-repairs.md) 在升级时自动执行并先备份；修订 ADR-0159 第三条（开发工具产物里被读回比对的取值改用英文 id）

## 背景

ADR-0159 让界面文字只在语言资源里，但还有一类中文不是界面文字，而是写进文件或账本、之后又被代码读回比对的取值：
`asset.ctx_orient` 的「竖屏 / 横屏」、`ctx_length` 的「速食 / 短 / 中 / 长」、`ctx_quality` 的「低画质」、
`entity_link.label` 的「官方网站 / 博客」、出演者标记 `asset_tag.tag` 的前缀「演员:」，以及封面日志、候选 CSV、
资源缓存里的结论与来源取值。

这些值同时承担了两件事：代码按字面比对，界面又直接把它显示出来。英文界面下侧栏写着「竖屏」、资料页链接写着
「官方网站」；改显示就要改数据，旧行随之对不上。前端为了比对，在 `frontend/src` 里留着一串「不是界面文案」的
中文字面量，SQL 里也有 `NOT LIKE '演员:%'` 这样的重复字面量。

## 决策

**一、适用范围。** 写进文件（数据根里的日志、复核 CSV、JSON 缓存）或账本、之后被代码读回比较、本身不是给人读的句子的
取值，用英文稳定 id。只在一次运行内比较、写出后不再被代码读回的取值也照此写，但不需要兼容旧值。

**二、id 的写法。** 小写英文，多个词用连字符：`portrait`、`landscape`、`quick`、`short`、`medium`、`long`、`low`、
`official-site`、`blog`、`needs-review`。前缀写成 `<id>:`，出演者标记是 `performer:<名字>`。本身已是通用写法的值
（`4K`、`1080P`、`720P`）不改。

**三、显示一律按界面语言。** 界面上不再直接显示取值：后端给 code（`label_code`、`message_fields`），前端用 `t()`、
`serverLabel`、`codedText` 或按 id 取译文；命令行按 `cli` 命名空间的资源显示。中英文案与改 id 在同一次改动里写。

**四、旧值兼容。**

- 账本：由迁移一次改写（本次为 `0057_stored_values_english_ids.sql`），写入方与读出方同一版本上线。迁移只改带旧值的
  行，重复执行不改动任何一行。撤回用的行快照（换版搬迁、升级补修回执）里存着原样的行，一并改写。
- 文件：数据根里旧的日志、CSV、缓存不改写，读入时先按对照表归一再比较。对照表放在定义新 id 的常量旁边，或放进
  内容数据文件（`src/peach/catalog_vocabulary.py` 的「旧版账本取值」「旧版文件取值」两节、`scripts/legacy_values.py`）。
- 地址参数与输入：旧书签、历史地址、用户脚本与人手填的输入可能一直带着旧值，长期照认。读入时归一（`orient=竖屏`
  当作 `orient=portrait`），生成的新链接只写 id；输入侧拒收与新 id 同义的旧写法（以 `演员:` 开头的标签名同样不能当
  内容标签加）。
- 随包种子与外来数据包里的旧值在导入时归一，不改已发布的数据包。

**五、不适用的取值。**

- 外站页面原词与按原词匹配的正则、词表（`公式サイト`、`ブログ`）。
- 标签名、genre 规范名与别名、技术标签（`横屏`、`低画质` 作为 `asset_tag` 的标签名时是标签，不是画幅取值）、
  `LENGTH_TAGS`、`TECH_TAGS`、`素人`。
- 厂牌名、公司名、平台名这类专名（`T-POWERS`、`X @handle`），以及真实目录名（`云下载`）。
- 参与哈希或作键的值（如口味书签后缀）：改了就对不上已存的键，存储侧保持原值。
- 给人读的备注、来源串与证据句：它们不被比对，按 ADR-0159 走 code 或保留原文。
- 已不再写入、只剩兼容读的历史值（如 `download_task.failure_detail` 的旧原文开头）。

## 不采用

- **只在界面上加一层中文到英文的映射，存储不改**：比对与显示仍绑在同一个中文词上，前端继续留着中文字面量，新写入还是中文。
- **账本取值也只在读入时归一，不迁移**：每条 SQL 都得同时认新旧两种写法，`LIKE`、`GROUP BY`、索引查找都会漏掉一半。
- **把旧值对照写在各自的模块里**：会让后端中文计数门槛（`check_backend_copy.py`）的条数上升；对照表是数据，归内容数据文件。

## 后果

- 英文界面下侧栏的画幅、统计页的分档、资料页的通用链接名显示英文。
- 首次升级到这个版本时，迁移改写账本里的这几列；本机实测约 2.1 万行画幅与时长档、四百多行画质档、一百五十条链接名、
  五千七百条出演者标记，耗时在一两秒以内，迁移前照常整份备份。
- 只读端在写入端迁移并同步之前不能读新结构的账本，这与 ADR-0126 的读取端顺序相同；旧版只读端读到迁移后的账本，
  会把 `performer:` 标记当成普通标签显示。
- 以后新加会被读回比对的取值，一开始就写 id，界面另配译文。
