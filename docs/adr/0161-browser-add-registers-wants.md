# ADR-0161：浏览器添加可以登记「想要」

- 状态：已采纳
- 日期：2026-11-14
- 关系：扩展 [ADR-0090](0090-want-list.md)「想要」的登记入口；表结构、对账与清单页不变

## 背景

浏览器添加（用户脚本）没搜到可下载的磁力时，番号只留在用户脚本的「其他任务」里，标为已读就没有了。用户访问的
作品页里也常有还没发行、或暂时没有资源的番号，这些正是「想要」要记的东西，但想要清单只能在 Peach 里按番号、
从 Feed 或关注条目登记。

## 决策

**一、没搜到资源时按设置自动登记。** 浏览器添加队列判定「无资源」后，若账本设置 `javBrowserWantOnNoMatch`
不为 `false`（缺省即开启），按番号登记进想要；已在库、已登记的照原样跳过，写入失败只记日志，不影响队列。
设置跟着账本走，入口在「下载 → 浏览器添加」那一节。

**二、用户脚本可以直接登记。** 新增 `POST /api/jav-browser/want`，用浏览器添加专用令牌鉴权，正文 `{"code": ...}`，
返回该番号的状态与 `want: {phase, created}`。单条状态 `GET /api/jav-browser` 与 `GET /api/jav-browser/identify`
带上 `want`：未登记为 `null`，已登记为清单上的那一段（待找、未发售、暂时放弃、已入库）。旧版 Peach 没有这个字段，
用户脚本据此决定是否显示「加入想要」。

**三、两条入口都用想要清单的按番号登记**（`wants.add_code`），`origin` 记 `code`：登记的就是一个库外番号，与手输番号同一种形状。
不新增来源值，`want_item.origin` 的 CHECK 约束与迁移不动。用户脚本那条在路由层走 `web_wants.w_wants`，登记后立即取资料；
自动登记在入库队列里只写这一行，封面与资料由新作的定时刷新顺带补上，入库模块不依赖 web 层。

## 理由

- 想要记的是意愿；用户在浏览器里点过「加入」又没搜到，或看了一部还没发行的作品，意愿已经表达过一次，不必再到 Peach 手输。
- 复用同一个写入口，取资料、封面、去重与「已在库拒绝」的判据只有一份。
- 自动登记是默认行为，所以给开关；登记错了在清单页移除即可，不需要整批撤回。

## 后果

- 想要清单目前不会自动重找资源（`wants.record_search` 与 `pending_targets` 尚无调用方），自动登记的条目要靠清单页按需查资源或用户手动处理。
- 自动登记与手输番号在 `origin` 上不可区分。
